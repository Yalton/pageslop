  <name>Task 1: Tag query module, worker enrich handler, and backfill</name>
  <files>src/lib/db/queries/tags.ts, src/workers/scrape.worker.ts, src/lib/queue/boss.ts</files>
  <action>
1. Create `src/lib/db/queries/tags.ts` with these functions (use `@/lib/db/client` for the db import, following the pattern in queries/links.ts):
   - `upsertTag(userId: string, name: string, source: 'rule' | 'user' | 'llm'): Promise<Tag>` — normalize name to lowercase trim, insert with onConflictDoNothing on (userId, name), if no row returned (conflict), select existing row. Return the tag.
   - `linkTagToLink(linkId: string, tagId: string): Promise<void>` — insert into linkTags with onConflictDoNothing (the unique constraint from Plan 01 prevents duplicates).
   - `getTagsForLink(linkId: string): Promise<Tag[]>` — inner join linkTags with tags on tagId, where linkId matches. Return {id, name, source}.
   - `deleteLinkTag(linkId: string, tagId: string): Promise<void>` — delete from linkTags where linkId and tagId match.

2. Add `enqueueEnrichJob` to `src/lib/queue/boss.ts`:
   ```typescript
   export async function enqueueEnrichJob(linkId: string) {
     const b = getBoss()
     await b.start()
     await b.createQueue('enrich')
     await b.send('enrich', { linkId }, {
       retryLimit: 2,
       retryDelay: 10,
       expireInSeconds: 120,
     })
   }
   ```

3. Update `src/workers/scrape.worker.ts`:
   a. Import `enrich` from the enrichment module using relative path: `../lib/enrichment/classify` (worker uses relative imports, not @/ alias).
   b. Import schema tables needed for tag operations.
   c. After scrape completes successfully (after the rawContent insert), enqueue an enrich job: `await boss.send('enrich', { linkId }, { retryLimit: 2, retryDelay: 10, expireInSeconds: 120 })`. Do this INSIDE the scrape handler, after rawContent insert has completed, using the same boss instance.
   d. Register a second queue handler in main():
      ```
      await boss.createQueue('enrich')
      await boss.work<{ linkId: string }>('enrich', { localConcurrency: 10 }, async ([job]) => { ... })
      ```
      The enrich handler should:
      - Fetch the link row (need userId, title, description, domain)
      - Fetch rawContent for linkId (need bodyText)
      - If no rawContent found, log warning and return (job completes, no crash)
      - Call `enrich({ bodyText, existingDescription: link.description, domain: link.domain, title: link.title })`
      - Update link with description (only if link.description is null — user edits win) and category: `db.update(schema.links).set({ description: result.description || undefined, category: result.category, updatedAt: new Date() }).where(eq(schema.links.id, linkId))`
      - For description: ONLY set it when the current link.description is null. If user has already edited it, do not overwrite.
      - For each tag in result.tags: upsert the tag (userId, tagName, source='rule'), then insert linkTag. Use the same inline logic as the tags query module but with the worker's local db instance (not the @/lib/db/client serverless one). The worker has its own `db` variable.
      - Log completion.
   e. Add backfill function that runs once at startup (after boss.start, before boss.work):
      - Query all links that have rawContent but category IS NULL: `SELECT links.id FROM links LEFT JOIN raw_content ON raw_content.link_id = links.id WHERE links.category IS NULL AND raw_content.id IS NOT NULL`
      - For each result, enqueue an enrich job using `boss.insert([...])` in batches of 50 with a 100ms delay between batches.
      - Log how many links were queued for backfill.

Important: The worker file uses relative imports (../lib/...), NOT @/ alias. It runs via tsx as a standalone Node process.
