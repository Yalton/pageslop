    - crossLinkNodes populates connectedLinks array on each node with GraphLink references
    - crossLinkNodes is safe to call BEFORE d3 initialization (works with string IDs in GraphLink.source/target)
    - Performance: buildGraphData with 5000 nodes (each having 3-4 tags) completes in under 500ms
    - CATEGORY_COLORS has an entry for every value in CATEGORIES plus 'Other'
  </behavior>
  <action>
    1. Install react-force-graph-2d: `npm install react-force-graph-2d`

    2. RED: Create `tests/graph/graph-utils.test.ts` with failing tests covering all behaviors above. Import types from the not-yet-created graphUtils.ts. Use vi.fn() or direct function calls — no mocking needed since this is pure logic. For the performance test, generate 5000 fake LinkWithTags objects with randomized tags from a pool of ~50 tag names, measure Date.now() before/after buildGraphData call, assert < 500ms.

    For the crossLinkNodes tests, verify that BEFORE any d3 processing (i.e., when GraphLink.source and GraphLink.target are still plain string IDs), calling crossLinkNodes correctly populates neighbors[] with actual GraphNode objects (not strings).     3. GREEN: Create `src/components/graph/graphUtils.ts` implementing:
       - `GraphNode` interface: `{ id: string; link: LinkWithTags; neighbors?: GraphNode[]; connectedLinks?: GraphLink[] }`
       - `GraphLink` interface: `{ source: string; target: string; sharedTagCount: number }`
       - `GraphData` interface: `{ nodes: GraphNode[]; links: GraphLink[] }`
       - `CATEGORY_COLORS`: Record<string, string> mapping each Category to a Tailwind color value (Technology=#3b82f6/blue, News=#ef4444/red, Reference=#8b5cf6/violet, Entertainment=#f59e0b/amber, Shopping=#ec4899/pink, Social=#06b6d4/cyan, Education=#10b981/emerald, Finance=#84cc16/lime, Health=#f97316/orange, Creative=#a855f7/purple, Other=#6b7280/gray)
       - `NODE_BASE_RADIUS = 5`
       - `NODE_TAG_SCALE = 0.4`
       - `buildGraphData(links: LinkWithTags[], visibleCategories: Set<string>): GraphData` — filter by categories (empty set = show all), build tag->linkIds index, compute deduplicated edges with sharedTagCount using sorted-pair key in a Map, return { nodes, links }
       - `crossLinkNodes(data: GraphData): void` — CRITICAL DESIGN: Build a `nodeMap: Map<string, GraphNode>` from `data.nodes` (keyed by node.id). Iterate `data.links`, read `link.source` and `link.target` as STRING IDs (they are still strings at this point — d3 has not yet replaced them with object references). Look up the corresponding GraphNode objects from nodeMap. Initialize `neighbors` and `connectedLinks` arrays if not present, then push the resolved GraphNode references to each other's `neighbors[]` and push the link to each node's `connectedLinks[]`. This approach is safe to call inside useMemo BEFORE d3 initialization, because it resolves string IDs to objects via the nodeMap rather than relying on d3's runtime object replacement.

    4. REFACTOR if needed: ensure all tests pass, clean up.

    IMPORTANT: Do NOT use `any` types. Import `LinkWithTags`, `Category`, `CATEGORIES` from `@/types`.
